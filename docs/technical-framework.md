# Technical 統一框架：既有模組接入

2026-11-05。現行政策為 `evidence-resolution-v13-jorc-interval-screening`。
以下前三階段記錄保留實作歷程；現行31群組的區間比較以本文末段的
JORC Table 1 接入為準。沒有建立具證據支持的全體唯一點排名。

## 唯一資料流

`原件 → 原有 Evidence / Study Case → Selection → unified_observations → framework_fields → 既有分析與 R 引擎`

主 CLI 在取得 Selection 後只建立一次共用觀測，明確傳給
`prepare_technical_panel(..., observations=...)` 與
`analyze_profiles(..., observations=...)`。沒有模組級快取、第二資料庫或另一套評分器。
兩個函式仍可獨立呼叫；不提供 observations 時才自行建立共用觀測。

## 模組責任

| 位置 | 責任 |
|---|---|
| `config/evidence_policy.json` 的 `technical_profile.framework` | 三軸、既有 quantity role 對應、缺少哪些範圍欄位、跨指標方案一致性欄位 |
| `technical.py` 的 `framework_fields` | 為共用觀測增加用途分類，不改值、身分、去重、原有資格或 Project 外推 |
| `technical.py` 的 `analyze_profiles` | 沿用既有觀測與證據輸出，再產出專案×三軸的覆蓋與缺口摘要 |
| `analysis.py` 的 `prepare_technical_panel` | 沿用既有數值契約，檢查構面角色與跨指標方案；權重依明示準則順序組裝 |
| `cli.py` | 共用一次觀測結果並交給上述函式，不加入科學判讀分支 |

框架代碼為 T-R（回收／分離）、T-I（處理投入）、T-P（產品性質／處理限制）。
沒有重新定義既有 T1；舊 T-A/T-B 敘述規則只作分類來源，不改成序位分數。

## 防止誤用

- 浮選、浸出與全流程方案的回收角色歸入 T-R，但保留給料、終點、元素、試驗尺度及來源；分類相同不代表可直接互排。
- 酸濃度、溫度、原礦品位、礦物賦存比例、文件成熟度與試驗數量保留為背景，不因為是數字就變成 Technical 績效分數。
- 同一回收數字的原句提到酸耗，不會讓該回收數字又成為 T-I 藥耗。非數值主張可以提供多軸的敘述證據。
- 不同 quantity 角色矛盾時不放行；同一 case_id 的回收與品位仍須有一致的 scope、有效日期／日期角色、scenario、basis、feed、endpoint 與 scale。
- 同一案不同方案不取最大、最新或最差值。不同來源日期若未能建立共同方案，在現有保守條件下仍需補證據。
- 不補零、不補平均、不按各案資料量重新配權；Project 分數仍為 NULL，覆蓋狀態不是品質排名。
- 既有兩案 TPR/TPG 示範保留原設定。TPG 的線性偏好假設沒有擴大成所有產品共同的 T-P 量尺。

紀錄數不代表獨立實驗數，也不會將跨範圍的數值平均。

舊快照的 configuration 未包含 framework，因此不增加這些新輸出／欄位。

## 擴充方式

新原件與量測仍經原有辨識／claims、Evidence、Selection 與共用用途契約。
新增明確物理量時，在原設定中指定 quantity role 與三軸對應；沒有專案名稱分支。
要新增 MCDA 準則，另須在既有 numeric_model 明示可比契約、效用函數、
準則順序與固定總權重，不因 framework 分類成功就自動新增分數。

本次真實回放使用已凍結 Selection：1,825 筆觀測、31 個群組，產出93列三軸摘要。
前次原件審查新增找到的來源數值，尚未藉本次架構修改自動寫入正式觀測。
31 群組與歷史39群組不是同一母體；來源限定數值覆蓋亦不等於共同 MCDA 樣本。

## 現行版本：JORC Table 1 骨架與31群組區間比較

依據 [JORC Code 2012 Table 1](https://www.jorc.org/docs/JORC_code_2012.pdf)
第1節樣本與前處理、第3／4節冶金因素、第4節研究狀態、代表性、
有害元素及產品規格建立七項證據索引。處理投入是依冶金因素及成本
延伸的研究欄位；JORC並未規定本研究三軸、權重或分數。
這份索引不是逐案JORC合規認證；有相關敘述也不表示已完成所需試驗。

只修改現有 `technical.py`、`analysis.py` 與政策設定；沿用 Selection、
共用觀測、來源身分及原SQLite。原兩案設計面板作為較窄的驗證面板保留，
不再充當全部31案的進場條件。`analyze_profiles` 在相同CLI中自動執行新分析。
`--skip-r`只略過原R批次，新區間分析仍在Python執行；它不代表已執行原R全套分析。

**技術表現**與**證據成熟度**分成兩份輸出：

- `technical_screening_matrix.csv`：各案各軸的條件效用範圍。
- `technical_evidence_maturity.csv`：設計／試驗尺度、樣本標籤、代表性與缺少的背景欄位。
- `technical_jorc_table1.csv`：七項Table 1索引與原觀測／證據IDs。

成熟度不加權、不作乘數、不提供整案成熟度總分。缺少研究日期、試驗尺度、
統計量或樣本數不再自動否決來源數字；來源無效、數字衝突、物理量、元素基準
或製程邊界不同仍不能冒充同一觀測，但其專案照樣進場，該格改成未知區間。

### 條件量尺與外推

四個邊界情境為精礦TREO、Nd/Pr浸出／解吸、Dy/Tb浸出／解吸、混合稀土產品TREO。
每個情境都保留全部31群組與固定三軸權重，不因缺值刪案或逐案重配權。
這四個情境是同一模組的邊界敏感度，不是四個資料庫，也不是可互換的整體製程排名。

採用明示的研究假設：回收率、TREO產品品位除以100作線性效用，ppm除以1,000,000。
品位只是濃集程度代理，不能當合格銷售產品分數。不同已列明氧化物集合、
粗精礦／精選精礦及設計／實驗結果的可比性均為條件假設，而非物理等價事實。
MREO不會偷換成TREO；單一元素也不會偷換成總稀土。

`REPORTED_CASE_PROXY`用所有合格來源觀測的最小／最大值包住已報告結果，
不取最好值或平均。最高值報告仍保留為最高值，不當平均績效；
這個包絡不能推論未試樣本、母體或未來運轉表現。
`PROJECT_TRANSFER_STRESS`則只容許已具整案目標代表性依據的值縮窄區間，
其他格恢復完整未知域[0,1]。這是外推假設壓力測試，不是重新排除專案。

投入軸尚無跨藥劑、純度、給料分母與產品邊界的共同效用，所以目前所有案的
T-I均保留[0,1]。既有酸耗等數值仍在原來源剖面與Table 1索引，不被刪除。
沒有以酸濃度當酸耗，也沒有拼接不同方案或已放棄路線。

### 排名與不確定範圍

`analysis.interval_mcda`以既有 `R/methods.R` 同一定義計算SAW、固定理想點TOPSIS、
線性偏好PROMETHEE II。未知格使用集合[0,1]，不抽均勻亂數、不補中點或零。
各準則包絡形成保守外包集合；極端角落可能不是可實現的同一流程方案，
因此不把它們發布成一列設計值。PROMETHEE名次範圍尤其可能偏寬。
並列涵蓋全部並列位置，不用資料順序打破平手。

測試平衡、回收優先、產品優先、投入優先四組設定，另加0.1步長的66組權重格點；
共70個具名／格點設定、67個不同權重向量。只代表已枚舉偏好，不宣稱連續偏好空間
均已求得最緊確界。±0、±5、±10個百分點是研究者設定的數值壓力測試，
不是來源誤差、信賴區間或成功機率。

輸出 `technical_interval_ranking.csv`（具名設定）、
`technical_rank_envelopes.csv`（枚舉偏好包絡）與
`technical_robust_pairs.csv`（分數區間互不重疊時的充分先後關係）。
後者只在所列情境內成立，不是跨礦型／生命週期的因果或商業結論。
