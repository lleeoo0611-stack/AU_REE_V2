# 本體論能辨認哪些稀土資料可以比較？

在 28 個專案的 62 個直接報值中，以單位和資源類別篩選得到 194 個候選欄位配對。加入資源聲明、門檻和物料的語意後，192 個可以描述性並列，1 個符合相同名義申報口徑，0 個有足夠證據證實操作定義完全相同。本輪辨認出可以提出哪一種比較主張，Census 實值增加 0 格，固定分母覆蓋率維持 2,501／3,034（82.43%）。[逐對結果](resource_pairs.csv) · [觀測及來源](resource_observations.json) · [原始發布版](../ree-project-census/nlp-retrieval-20261126/)

## 從 NLP 找頁到本體判讀

前一輪用相同 39 個留出專案做測試。可評分 49 題中，既有規則加 BM25 的前五頁命中 31 題，既有規則命中 24 題；第一頁均命中 24 題。候選頁次從 29 增至 265。Perenjori 新增 1 格離子吸附黏土**探勘模型**代碼，座標新增 0 格。這支持把 NLP 用在找證據頁，尚無同等翻頁成本下的優勢估計或真人省時數據。[NLP 組間比較](../nlp-census-ab-20261126/)

## 相同觀測、不同強度的比較

採用 2026-11-13 研究截日及當時選定的 MRE。固定三個欄位為礦石噸數、TREO 品位、含 TREO 量。28 個專案產生 699 個同欄位配對，其中 505 個已因資源類別或計量單位條件排除。下表分母一律是其餘 **194 個欄位配對**，涵蓋 106 個相異專案 ID 組合。同一組專案可能貢獻多個欄位配對。日期隨觀測一併保留，跨專案比較允許各自在截日前採用不同的估算日期。

| 主張 | 符合 | 明確衝突 | 證據不足 | 重複聲明 |
|---|---:|---:|---:|---:|
| 可並列各自發布的值 | 192 | 0 | 0 | 2 |
| 相同名義申報口徑 | 1 | 178 | 13 | 2 |
| 相同操作定義 | 0 | 179 | 13 | 2 |

Donald MIN5532 和 WIM100 是唯一的名義匹配。兩者都是乾基全礦、Measured + Indicated + Inferred 合計、1.0% 重礦物門檻。Donald 的分析粒徑為 20–250 μm，WIM100 為 38–710 μm。可以比較各自報了多少乾礦；若要回答「相同粒徑定義下哪案更多」，需要可重算的資料。Mt Stirling–Yttria 和 Yttria 兩個不同 PDF 的第 2 頁重刊同一資源表，影響噸數與品位兩個欄位。去重後留下 105 組專案可作描述性對照。[原件與頁碼](../../data/validation/ontology_reference_20261126.json)

13 個尚待判定的欄位配對涉及 9 個專案。每一對至少一端缺門檻所量的物質及乾濕基，另有 5 對缺 TREO 的完整氧化物組成及是否含釔，4 對缺估算範圍。後續 NLP 可優先搜尋這些定義及其所屬資源表，並要求回傳 PDF 頁碼。在全體 194 個候選內，每一對至少一端尚缺已編碼的完整操作門檻定義，因此不能把嚴格匹配為零外推成全澳洲沒有可比案例。門檻「已知衝突」與「證據不足」由不同欄位記錄，可以另查同一配對同時缺了哪些條件。[逐項判定與缺證](resource_pairs.csv)

以 14 份原件檢查 12 個指定欄位配對，兩個比較層級的判定都與原件對照一致。案例包含 8 個資源欄位配對及 4 個 Jupiter／Splinter Rock 氧化物配對。後者延續先前成果，另外列示。案例是刻意挑選的，部分在設計期間已討論，另兩組的預期結論在第一次核對前獨立保存。這提供逐例驗證，全庫精確率仍未量測。[對照驗收](control_results.csv) · [氧化物明細](resource_oxide_extension.csv) · [採用的本體與證據標準](design.md)

## 用資料計算 MCDA 權重

對同一批完整資料固定效益方向、評分函數與 SAW 加總法，比較等權、CRITIC 與熵權。發布的準則分數和證據連結都是原輸入。先重現兩個面板共 23 筆發布的 SAW 名次及分數（容差 10⁻¹²），再換權重。各準則的最大最小值、標準差和相關係數均在估權樣本內計算。逐案留出時，用其餘專案估權、回到同一完整名單評分，量的是排名敏感度。

| 面板／權重情境 | 與發布名次相比 | 留一案估權的第一名 |
|---|---|---|
| 西澳政府資源量，17 案，CRITIC | 含量 54.19%、品位 45.81%。North Stanmore 10→9，Browns Range 9→10。 | 17／17 次都是 Mt Weld。 |
| 同一面板，熵權 | 含量 13.53%、品位 86.47%，13 案換位。 | 17／17 次都是 Mt Weld。 |
| 發行人資源與基礎設施，6 案，保留原領域比例 | 資源占 1/3、基礎設施占 2/3。領域內使用 CRITIC 或熵權均有 0 案換位。 | 兩種算法各 6／6 次都是 Jupiter。 |
| 同一面板，五項直接用 CRITIC 估權 | 資源 20.11%、道路 15.17%、鐵路 13.58%、電力 20.18%、港口 30.96%。Nolans 4→5，Mount Ridley–Central Mia 5→4。 | 全樣本以 Jupiter 居首；排除 Dubbo 估權、回評六案時，首位變成 Dubbo。 |

建議使用 CRITIC 產生可重播的資料驅動權重，與等權、熵權及逐案留出結果一併呈現。西澳只含兩個準則，相關項在 CRITIC 權重比例中抵銷。六案面板樣本小，四項基礎設施距離又可能重複表達區域條件。改用全準則估權可移除人訂的領域比例，但無法移除指標選擇或評分函數的影響。這些面板沿用既有納入條件，與前面的嚴格 MRE 比較分開；西澳政府摘要用於探索性篩選。這次權重試驗沒有把 194 個候選混入正式排名，也沒有改寫任何正式排名。[各案名次](weighting_ranks.csv) · [逐案留出](weighting_leave_one_out.csv) · [輸入指紋及權重](weighting_summary.json)

## 重現

於專案根目錄使用已安裝本專案依賴的 Python。前兩行可只用 Git 內的資料重算權重並核對已交付的配對。第三行從既有靜態 PDF 套件重新驗證原件並產生比較結果，將參數所示路徑換成套件的 assets 目錄。最後再驗一次重產的配對。

```sh
python tools/ontology_weights.py
python tools/check_ontology_controls.py
python -m tools.ontology_comparability --assets work/coverage-locked-kit/assets
python tools/check_ontology_controls.py
```

本輪使用研究用腳本讀取同一份 Phase 22 輸出與原件，沿用既有單位核對與氧化物表解析。語意模型採版本化的本地對照表，部分條件以聲明 ID、來源指紋、頁碼和原文片語校驗。新報告需取得相應的條件證據，才可支持相同的比較主張。[可執行模型](../../tools/ontology_resource_model.json) · [輸入範圍與指紋](resource_summary.json)
