## 從原件到用途判定

- 資源擷取重用 `pdf_extract` 的版面及 `technical_tables` 的數字解析。以已綁定的 Project、文件 SHA、實體頁及原始表列標記找欄位，保留原字串、單位、表列定位或正文位置。跨頁或跨文件資訊需要來源明示引用。數值相同、標題相近、單位相同皆不構成估算相同的依據。
- 技術擷取重用 `technical_tables` 的列欄幾何和 `technical_compare` 的合同。原始 proof 重查表標、樣品和 token，同一報告明示的試驗程序可引用到各元素觀測。樣品、材料、量別、尺度、流程與實測或設計的語境分別留有原文。
- `resource_use` 集中先前研究腳本的選定聲明及精確單位換算核對。舊研究工具和新的 `observation_semantics` 使用同一組閘門。共同回傳用途、判定、缺項、正規值及證據。既有 RDF／SHACL 原型維持歷史實驗範圍，本次使用版本化用途規格與本地證據約束。
- 擷取階段產生來源及關係候選。判定階段只讀凍結的擷取結果。完整基準包含上一輪審查支持的 88 筆資源來源紀錄。下面另外列出純自動重建老成果的效果。[用途與採用門檻](../../config/ontology/shadow_profiles_v1.json)

## 技術語境的實測改善

Dubbo 的第 29 頁有 Phase B 瓶滾浸出程序，第 30–32 頁的三個樣品表提供 269 筆可用讀值。E1 綁定樣品與表號，保留程序所載的 **28 天、50 wt% 固體、1 kg 取樣與溶液 ICP-OES**。原表的酸濃度用 g/L，流程用 kg/t，兩者依各自上下文保留。HLC-East 的 Er 表列 **−0.5%** 保留原文及受阻決定，剩下 111 筆技術觀測不適用這個樣品內比較用途。

在 381 筆技術觀測上，缺流程階段由 **331 降至 62**，缺尺度仍為 **52**。抽查顯示 Donald 累積的 50 格無法確認單一實測尺度，Wolverine 的 2 格屬壽命期工程指標，尺度依工程設計理解。Cummins 的試劑為工程設計情境。新增語境聚集在 **1 個專案、3 個樣品表、1 個實驗計畫**。T1 沿用原本的正式定義。[技術審查計數](comparison.json)

## 原件重播

在 repository 根目錄，以原專案環境和先前的 SHA 命名靜態檔執行。以下 `ASSETS` 是 gap173 靜態套件的資產目錄，`FROZEN_RUN` 是含 `technical_cells.csv`、`resolved_evidence.csv` 與 `census.csv` 的 `20261121T180616-f9542b39`。兩次影子比較耗時約 135 及 132 秒，三份主要結果逐位元一致。

```sh
python -m au_ree_v2 semantic-shadow --shadow-originals "$ASSETS" \
  --shadow-run "$FROZEN_RUN" --shadow-output work/shadow-replay
```

正式離線流程可附 `--semantic-shadow --shadow-originals "$ASSETS" --shadow-output work/shadow-side`，正式出表完成後，會核對 Census 與技術讀取投影，再產生獨立影子結果。舊的 Gap173 來源收據與目前登錄的指紋不同。重跑正式流程使用 coverage-locked 的相符收據及原件，影子評估採與凍結專案和用途相符的讀取投影。
